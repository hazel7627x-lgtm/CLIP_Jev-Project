# Stage2 学生后校准结果与交接

芙芙的鱼负责的学生后校准比较已完成。六个 KD 学生分别拟合了温度，同时重放三个 CE 学生作为对照核验。无需再运行 Colab，不需要重新训练。

在已使用过的开发集上，直接给原始 KD 学生做温度校准，就能改善其概率质量。Teacher 校准没有在所有概率指标上胜过这个简单对照。因此论文应保留两条路线的比较，不能把概率改善全部归功于 Teacher 校准。

## 做了什么

- 固定 CE、原始 Jev KD、校准 Jev KD，各三个种子：20261010、20261011、20261012。
- CE 与 KD 均使用既有学习率 0.0003 的模型；KD 固定 alpha=0.75、训练 tau=2。全部 checkpoint 沿用此前开发集选出的结果，没有重新选模。
- 对每个模型，在原有 val_fit 400 条上拟合一个正温度 T，以 NLL 最小为准。使用 Day2 的同一网格：0.05 至 20 的 401 个等比点，另包含 T=1；精确平局时选择更接近 1 的温度。
- 在原有 val_select 400 条上报告校准前后的指标。此处是开发集描述性分析，不是新的独立确认。
- 后温度只作用于最终 Student logits：softmax(logits/T)，与训练 KD 的 tau=2 是两个不同参数，不能再次把训练 tau 乘进去。
- 没有读取或评价历史 1000 条和补充 200 条的特征与预测，没有扩大 alpha 搜索。

## 开发集结果

下表为三个种子的均值。Macro-F1 越高越好；NLL、ECE、Brier 越低越好。ECE 使用原协议的 10 个等宽区间。

| 训练方式 | Student 后处理 | Macro-F1 % | NLL | ECE % | Brier |
|---|---|---:|---:|---:|---:|
| CE | 无 | 63.957 | 0.896287 | 8.207 | 0.515484 |
| CE | 温度校准 | 63.957 | 0.876025 | 6.437 | 0.512083 |
| 原始 Jev KD | 无 | 66.754 | 0.855461 | 6.908 | 0.481486 |
| 原始 Jev KD | 温度校准 | 66.754 | 0.827361 | 5.930 | 0.478421 |
| 校准 Jev KD | 无 | 66.885 | 0.832449 | 5.684 | 0.478685 |
| 校准 Jev KD | 温度校准 | 66.885 | 0.829426 | 6.402 | 0.480132 |

正标量温度不会改变类别排序，所以 Macro-F1、Accuracy 和各类别 F1 均保持不变。这是正确行为，不是没有运行。

## 应如何解释

**简单的 Student 后校准已覆盖不少概率改善。** 原始 KD 的 NLL 从 0.855461 降到 0.827361，ECE 从 6.908% 降到 5.930%。它的 NLL、Brier 均略低于不做学生后校准的校准 KD；后者的 ECE 略低，且原本分类 F1 高 0.131 个百分点。因此不能概括为任何一种方案全面胜出。

**两类 KD 都做学生后校准时，原始 KD 的平均 NLL、ECE、Brier 更低。** 这不证明 Teacher 校准无用，也不代表统计显著；它说明当前没有证据支持 Teacher 校准相对简单后校准拥有全面、不可替代的概率优势。

**按 NLL 拟合温度，并不保证 ECE 和 Brier 一起改善。** 校准 KD 再做学生温度校准后，NLL 从 0.832449 降到 0.829426，但 ECE 从 5.684% 升到 6.402%，Brier 也升高。应保留此结果，不根据 ECE 重新换温度或网格。

蒸馏相对 CE 的开发集分类差距仍然存在：原始 KD 比 CE 高约 2.80 个百分点。后校准处理的是置信度，不会消除或制造这个分类差距。以上比较均不能替代独立评价；本包仅提供种子间样本标准差和逐种子配对差值，没有把标准差当作置信区间。

## 核验与运行环境

本地运行环境为 PyTorch 2.11.0+cpu、NumPy 2.3.5、Python 3.12.14，FP32、CPU 两线程。原模型训练／预测为 T4 FP32，PyTorch 2.11.0+cu130、NumPy 2.1.3。此处是冻结分类头的 CPU 推理与温度拟合，不是重新训练，也不是推理成本测量。

- 九个模型均以 weights_only=True 加载 state_dict，按既有 2048→512→3 结构重放，关闭 Dropout。
- CPU 重放与原 GPU 开发集 logits 的最大绝对差为 0.0000011921，所有预测类别一致。报告保留原 GPU val_select logits 作为统一基准；val_fit logits 来自本次 CPU 重放。
- 三个 CE 的拟合温度与既有 Day2 温度一致，校准前后开发集指标也复现。
- 逐条重算了 14400 行导出预测的指标，并核验九个温度的网格最优点。14400 行包含模型与处理方式重复，独立样本是原有 400 条 val_fit 加 400 条 val_select，不能作为新增样本量。
- FINAL_AUDIT.json 为输出复核，replay_audit.json 为逐模型重放差异。两者与 COMPLETE.json 一起保留。

## 文件怎么用

- 先读本说明；summary.csv 是开发集均值与样本标准差，per_seed.csv 是两份开发数据的逐种子结果。
- paired_deltas.csv、paired_summary.csv 保存预定比较的配对差值。方向为文件中所写的“前者减后者”；概率误差指标负值有利于前者。
- protocol_LOCKED.json 是运行前固定的方案及输入 SHA256，student_temperature_LOCKED.json 是温度和模型对应关系。
- inputs 包含复现所需模型、特征和清单；outputs 包含逐条预测、原始 logits 和全部温度网格记录。
- PACKAGE_SHA256.json 提供包内逐文件校验值。

本轮已经完成，无需用户再跑 notebook。若需要从零复现：在另一个新目录复制 inputs、protocol_LOCKED.json 和 run_postcal.py，使用上述 CPU 环境执行 `python run_postcal.py run 新目录的绝对路径`。不要覆盖已交付结果。完成后可把 verify_outputs.py 复制到新目录运行，重算导出指标。脚本的 prepare 模式是本地来源归档步骤，依赖原始 ZIP 路径，复现计算不需要运行它。
